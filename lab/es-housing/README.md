# ES-HOUSING · 西班牙住房材料包（规格 + 骨架）

提案 #2。不要实现成可下单或自动提交政府网站的机器人。

## 要解决的痛

PAPER-011 已有 NIE / 租房 / 回国三张清单。旅居重复痛点是：**同一套材料在「看房 → 合同 → 入住 → 退租」各阶段缺的不一样**，且西语表格名和中文口头名对不上。

证据：011（NIE/租房模板）、006（租房对比/打包）、007（马德里购买力）。需求模型要求 ≥2 项目支持。

## 不做

- 不代填 sede.gob.es，不抢 cita。
- 不保存护照号、NIE、地址等到仓库或云端。
- 不做付费「移民顾问 SaaS」。

## 范围（MVP 规格）

1. 阶段：`viewing` / `contract` / `move_in` / `move_out`。
2. 每阶段一张清单，条目含 `zh` / `es` / `hint` / `optional`。
3. 输入：是否有担保人、是否带家具、合同是否已签。输出过滤后的清单。
4. 纯函数引擎 + `node --test`；页面可打印；数据只在 `localStorage`。
5. 默认 dry-run：生成清单，不发送邮件。

## 骨架

- `engine.js`：`buildPack(answers)` 现返回 `not_implemented`。
- `engine.test.js`：锁住「未实现」与未来不变量占位。
- 实现时另开目录或升为 `014/`，不要改 011 的 DEFAULT_TEMPLATES，除非只复用函数。

## 验收

- 四种阶段各有 ≥5 条；过滤逻辑有测试。
- 西语官方表名（如 `modelo` / `justificante`）与中文对照。
- README 写明「不是法律意见」。
